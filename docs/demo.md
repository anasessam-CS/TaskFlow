# عرض TaskFlow للمناقشة

## ترتيب العرض

1. **هدف المشروع** — إدارة المهام اليومية وعرض التقدم.
2. **التقنيات** — HTML وCSS للواجهة، وJavaScript للتفاعل، وPHP لطلبات الخادم، وSupabase Auth وPostgreSQL للبيانات.
3. **شرح قاعدة البيانات** — اعرض أعمدة tasks والعلاقة بين user_id وauth.users. اشرح مصدر UUID والحالات المسموحة وسياسات RLS.
4. **عرض مباشر** — سجّل دخول حساب تجريبي وأضف مهمة باسم «Prepare project slides». عدّلها، غيّر حالتها إلى Completed، وراجع العداد.
5. **إثبات العزل** — نفّذ M14 بحساب ثانٍ في نافذة خاصة، ثم سجّل الخروج واعرض إعادة التوجيه.
6. **نتائج الاختبارات** — اعرض جدول الاختبار اليدوي وملخص Maven، ووضح الفرق بين Passed وFailed وSkipped.
7. **لقطات العرض** — صوّر تسجيل الدخول، شاشة اللوحة بعد إضافة مهمة، نموذج التعديل، وملخص الاختبارات. استخدم بيانات الحسابات التجريبية بعد ربط قاعدة البيانات.

## أسئلة متوقعة

- **فين الباسورد بيتخزن؟** Supabase Auth هو اللي يدير كلمة المرور. PHP يمرّرها أثناء الطلب، ثم يحتفظ بالتوكن في جلسة الخادم.
- **إيه اللي يمنع مستخدم من فتح مهمة تانية؟** PostgREST يحدد هوية المستخدم من JWT، وRLS تقارنها بـ user_id لكل صف.
- **ليه التحقق موجود في PHP؟** المستخدم ممكن يبعث الطلب من غير المتصفح، لذلك PHP وقواعد PostgreSQL يطبّقوا الشروط على الخادم.
- **ليه JUnit 5؟** بيشغّل السيناريوهات ويقدم assertions وتقارير Maven. Selenium هو اللي يتحكّم في المتصفح.
